# 【迭代N】<内部标识>Agent工作区：AI纯文本回复被当JSON解析，每条消息误报console告警「Failed to parse JSON string」

页面定位：Agent 工作区 → 打开任一含 AI 纯文本回复的会话（示例：定时任务「喝水提醒」的自动执行会话 /agent-workspace/task/c08a007fc87946dc87845086512eeb2b）→ 按 F12 打开 Console → 查看 Warning

【预期结果】

AI 纯文本回复属正常场景，渲染消息时不应产生任何 console 告警或错误。

【实际结果】

每渲染一条纯文本 AI 回复即输出一条 warn：

Failed to parse JSON string: SyntaxError: Unexpected token '收', "收到，到点该喝水啦 "... is not valid JSON

刷新含 2 条 AI 文本回复的会话页， 每次固定 5 条 warn ；同一条回复因计算属性随重渲染反复求值而 重复 3 次 ；内容为空串时另有 1 条  Unexpected end of JSON input  变体。完整调用栈见截图。

两条独立调用链均指向同一个通用解析工具：

（1）SSE 流式接收： handleSseEvent → handleFinalResponse → getFinalContent →  解析工具；

（2）Vue 渲染期： hasChoiceCard  计算属性 → 解析工具。

根因：该工具解析失败时返回  {}  并顺带  console.warn ；但两个调用方都把失败当作预期分支且已兜底（ getFinalContent  回退为原始文本； hasChoiceCard  试解析整段回答以识别 CHOICE 卡片，AI 纯文本必然失败）。同模块 已有静默版本 （同样判断能否解析为 JSON，但不打日志），说明两类用法本应区分。

功能未受影响，但堆栈含前端监控 SDK 包装层，说明这些告警 会被采集上报 ；控制台被  SyntaxError  堆栈持续污染，开发/测试易误判为功能报错。

建议：上述调用点改用同模块的静默版本，或降级为  console.debug ； hasChoiceCard  建议缓存结果，避免重渲染重复解析。

控制台告警原文与完整调用栈（getFinalContent 与 hasChoiceCard 两条独立链路）、解析工具与其静默版本的代码对比、两个调用方的兜底逻辑、触发频次统计

## 根因
packages/<内部标识>-utils/src/common-utils.ts 中通用解析工具 `safeGetObject` 在 JSON.parse 失败的 catch 分支里直接 `console.warn('Failed to parse JSON string:', error)` 并返回 {}；而两个调用方都把解析失败当预期分支且已兜底（runtime-chat.ts 的 getFinalContent 回退原始文本、ai-message.vue 的 hasChoiceCard 用 hasPresentationComponent 试解析整段回答识别 CHOICE 卡片），因此每渲染一条 AI 纯文本回复（含空串变体）都会产生一次告警，且 hasChoiceCard 计算属性随重渲染重复求值导致同一条回复重复 3 次。

## 说明
把 `safeGetObject` 解析失败分支的 `console.warn` 降级为 `console.debug`，是单点最小改动：该工具是所有调用链（SSE 流式接收 getFinalContent → getAiMessageContent，以及 Vue 渲染期 hasChoiceCard → hasPresentationComponent）的共同出口，改一处即可消除全部 5 条告警（含空串的 'Unexpected end of JSON input' 变体），同时保留 debug 级别信息便于排查，不影响任何返回值与业务逻辑（解析失败仍返回 {}，调用方兜底行为不变），也不会被前端监控 SDK 采集上报。
